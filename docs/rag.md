# Hybrid RAG & Vector Memory: MailMind (InboxGuard)

## 1. Hybrid RAG Architecture

```mermaid
flowchart TD
    Q[User Query / Current Email] --> Parse[Query Understanding & Keyword Extraction]
    Parse --> Dense[Dense Vector Search (Cosine Similarity)]
    Parse --> Sparse[Sparse Metadata & Keyword Filter]
    Dense --> RRF[Reciprocal Rank Fusion / Weighted Merge]
    Sparse --> RRF
    RRF --> Filter[Top-K Candidate Selection]
    Filter --> Explain[Explainability Metadata Generator]
    Explain --> Context[Retrieved Historical Context + 'Why Retrieved?']
```

---

## 2. Retrieval Formulation

The Hybrid RAG engine computes a combined relevance score balancing semantic conceptual similarity with precise keyword matching:

$$\text{Score}_{\text{hybrid}} = 0.65 \cdot \text{sim}_{\text{vector}} + 0.35 \cdot \text{score}_{\text{keyword}}$$

Where:
- $\text{sim}_{\text{vector}}$: Cosine similarity between query embedding and email chunk embedding generated by `all-MiniLM-L6-v2`:
  $$\text{sim}(q, e) = \frac{\mathbf{q} \cdot \mathbf{e}}{\|\mathbf{q}\|_2 \|\mathbf{e}\|_2}$$
- $\text{score}_{\text{keyword}}$: Overlap ratio of extracted content tokens, boosted when terms appear in the subject or sender domain.

---

## 3. Explainability ("Why Was This Retrieved?")

To provide transparency during B.Tech project review and user inspection, every retrieved item includes an explicit rationale:
- **Hybrid match**: High cosine similarity combined with specific token hits.
- **Semantic vector match**: Conceptual meaning alignment even when exact phrasing differs.
- **Keyword match**: Direct term matches in subject line or header fields.
